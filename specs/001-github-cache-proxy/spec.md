# 功能规格：GitHub 下载缓存代理

**Feature**: 001-github-cache-proxy
**状态**: 已实现（2026-11-20）
**契约**: `../../contracts/openapi.yaml`（仓库根，唯一事实源）

## 概述

内网访问 GitHub 不稳定。本服务作为内网唯一的出网点，把 GitHub 的下载请求代理回来并落盘缓存；同一文件第二次被请求时直接从磁盘返回。

## 用户故事

**US-1 新机器装机不再依赖外网**
运维在一台能出网的机器上启动服务，其余开发机把 GitHub 地址改写到该服务。安装工具链时第一次下载由服务回源并缓存，之后的机器全部命中缓存。

**US-2 断网后仍能重装**
服务所在机器断网后，已缓存的文件仍可正常下载，用于重建环境。

**US-3 断点续传**
下载大文件中断后可以带 `Range` 继续，服务从缓存中返回对应字节区间。

**US-4 回源中断后可续传**
从上游下载到一半中断时，已下载部分保留在磁盘；下一次请求从断点继续回源，而不是从头重下。

## 验收标准

- AC-1 同一 URL 连续请求两次，第二次不再访问上游，且响应体现缓存命中。
- AC-2 GitHub Release 的 302 跳转由服务完成，客户端无感。
- AC-3 缓存命中时带 `Range` 返回 `206`，`Content-Range` 正确。
- AC-4 非白名单域名访问返回 `403`，且不发起上游请求。
- AC-5 客户端提供的 `Authorization` / `Cookie` 不会出现在上游请求中。
- AC-6 删除缓存目录并重启后服务仍可用，索引自动重建。
- AC-7 上游返回压缩内容时，代理保持原始字节与 `Content-Encoding` 一致，命中缓存后仍能正确还原。
- AC-8 回源中断后，下一次请求从已下载偏移继续，且仅在校验信息一致时复用已下载部分。
- AC-9 可通过 `/_entries` 列出当前缓存条目及其 URL、大小、时间和删除用的 `key`。
- AC-10 配置服务端 token 时，token 只出现在发往 GitHub 主机的 HTTPS 请求中，不会发往 CDN 重定向目标或额外域名。
- AC-11 上游返回非 2xx 时原样返回状态码；响应体过大时截断，`Content-Length` 与实际返回字节数一致。
- AC-12 可通过 `DELETE` 删除单条缓存或清空全部；删除后再次请求同一 URL 会重新回源，条目不存在时返回 `404`。

## 非功能需求

- NFR-1 默认仅监听 `127.0.0.1`；开放局域网必须显式配置来源网段。
- NFR-2 运行时依赖仅 Flask 与 requests。
- NFR-3 缓存可随时删除，不影响服务正确性。
- NFR-4 单实例实测 2.3MB Release 文件下载与命中回读正常。

## 范围之外

- 不做 HTTPS 监听（由内网反代或网络隔离承担）。
- 不做用户鉴权（依赖 CIDR 与网络隔离）。
- 不做多节点共享缓存。
- 不代理 Git 协议的 clone/push（仅 HTTP 下载）。

## 术语

- **上游**：被代理的 GitHub 域名。
- **前缀式 URL**：`/https://host/path` 形式的请求路径。
- **命中**：请求的 URL 已有完整缓存并可直接返回。
