# ADR-0001 用 Flask + requests 实现带磁盘缓存的代理

## 状态

已采纳（2026-11-20）。取代同日的 Go 实现草稿。

## 背景

内网访问 GitHub 不稳定，需要一台机器集中出网，其余机器从它读取工具链与 Release 资产。评估过现成方案：

- nginx `proxy_cache`：能真缓存，但本机无 nginx，且要额外维护配置与证书。

团队的技术栈是 Python，后续维护者为 Python 开发者。

## 决策

用 Flask + requests 实现，缓存、淘汰、Range、白名单全部在应用层完成，约 600 行。

理由：

1. “代理缓存”的核心是落盘与断网可用；nginx 方案虽能缓存，但需要额外组件，本机不可用。
2. Flask + requests 是团队最熟悉的组合，改起来不需要额外学习成本。
3. 依赖只有两个，`pip install` 之后即可在离网环境运行；部署在 Linux 拉取机上用 gunicorn 托管。

## 关键设计

- **前缀式 URL**（`/https://host/path`）而不是改写 Host 头。原因：mise 的 `url_replacements` 只做字符串替换，前缀式直接可用，不需要客户端支持自定义 Host。
- **服务端跟随重定向**，并校验每跳目标都在白名单内，避免通过 302 把代理变成 SSRF 跳板。
- **缓存键只与原始 URL 有关**，与重定向后的地址无关：同一个 Release 链接无论跳到哪里，缓存都稳定命中。
- **首次 Range 请求不缓存**：避免把半个文件当作完整内容存下来。
- **回源断点续传**：中断后保留半成品，下次用 `Range` 从已写偏移继续；用 `ETag` / `Last-Modified` 校验，避免拼接不同版本的内容。
- **不转发客户端凭据**：代理不应成为凭据的中转站；私有仓库用 `UPSTREAM_TOKEN`。
- **命中缓存时用 `send_file(conditional=True)`**，Range、ETag、HEAD 由 Flask 处理，避免自己实现字节切片逻辑。
- **单进程内按 URL 加锁**做并发去重；因此部署推荐 `gunicorn -w 1 --threads N`。

## 后果

- 需要自己维护（约 600 行），但边界清晰。
- 没有 HTTPS 监听，依赖内网隔离或前置反代。
- 无鉴权体系，权限靠 CIDR 白名单与网络隔离。
- 多进程部署时各进程独立缓存，命中率下降但不影响正确性，所以推荐单 worker 多线程。

## 替代方案复盘

- 如果将来需要“多节点共享缓存”，正确方向是引入对象存储（MinIO/S3）做后端，而不是给这个进程加分布式一致性。
- 如果出现 CPU 或内存瓶颈（大文件并发），再考虑换异步框架（FastAPI + uvicorn）或 Go 重写；当前实测 2.3MB Release 下载与回读无压力。
